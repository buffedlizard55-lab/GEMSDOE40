01 / THE QUESTION

Why did the best submission score 0.2778?

Full analysis ↗
MEASURED

It was a deletion, not a discovery.

The best file is the 0.2708 base minus 2,545 pixels (6.33 % of its mass), all of them 141–200 m from the provided catalogue, with 0 pixels added. Its minimum distance to a mapped fault is 224 m.

ALGEBRA

Every emitted unit must clear a bar.

With α = 0.2 and β = 0.8 and α + β = 1, one more unit of predicted mass changes the metric denominator by exactly 0.2 wherever it lands. So a dot only pays while its kernel credit exceeds 0.2 × DTI — at 0.2778 that means within 283 m of a hidden fault. This is the whole reason near-catalogue mass is expensive: those pixels earn nothing while the metric charges for them.

CONSEQUENCE

Credit per dot is the target.

Inverting the metric on the 16 recorded scores gives the hidden credit each file implies: the best averages ≈ 0.090 per dot at the family's own mass, the worst 0.016. Reaching 0.3195 at the same mass needs ≈ 0.103 — about 15 % better placement, not exotic new data.

02 / THE METHOD

Reid's contact solver, then a density, then dots.

Pre-registration ↗
01 · SOLVE

SI = 0 Euler contact.

Reid et al. (1990) eq. 2 with the arbitrary contact offset A — the structural index of a fault-like contact — solved on sliding windows of rtp (150 m continuation, windows 9, 15, 21) and of the once-differentiated iso_grav_anom (500 m continuation, windows 15, 21, 31), stride 4. A synthetic analytic contact is recovered to 0.3–1.0 m laterally and exactly in depth at zero noise — the solver is validated, so the real-data difficulty is a property of the data.

02 · WEIGHT

Shallow, tight, coherent.

Weight = exp(−depth/1200 m) × cross-window depth consensus (≥ 3 neighbours within 300 m, at least one from a different window) × lineament coherence (1 − λ₂/λ₁ of the local solution cloud) × cross-family corroboration (400 m / 600 m, uncorroborated solutions halved).

03 · EMIT

Anisotropic KDE, then dots.

The weighted cloud is smeared along each local lineament axis (σ 1.6 px along, 0.55 px across, 12 directions) into a continuous density in [0, 1], then sampled at 2.8 px maximum separation — just inside the metric's own 3 px kernel — under a 40,000-dot budget, with the provided catalogue and a 1 px ring removed.

The construction reads only training_features.tif, the sample template and the catalogue mask. It never reads labels.tif as truth, any prior prediction, or any proxy raster: construction_reads_labels_or_priors = false in the generation receipt.

03 / THE HONEST PART

What is measured, and what is not.

All measurements ↗

Measured. The file is a valid single-band float32 GeoTIFF in EPSG:32611 with the exact sample shape, transform and NaN footprint (7,111,787 cells outside, 40,000 in-footprint non-zero cells in [0.383, 1.000]). It is not a duplicate of any cached prior raster.

Not measured. Its leaderboard score. The catalogue surrogate (w = 0.0174) and the off-catalogue SGMC surrogate (w = 0.0376) are named proxies, and neither ranks the 16 recorded scores: ρ(catalogue-calibrated LM) = +0.100, ρ(SGMC off-catalogue) = +0.676, ρ(mass) = -0.676. The best recorded file sits *below* the chance line on the catalogue column because catalogue pixels are masked from scoring (DrivenData staff, 2026-09-16) — credit there can never be earned.

Therefore. The brief's own rule applies: the top hypothesis must beat the current holdout best before a submission slot is spent, and no instrument here can demonstrate that. The file ships with an explicit non-promoted status rather than a score promise.
