Every limitation below is either something that would change a decision if it were resolved, or something that currently prevents a claim. Nothing here is scored, and no organizer score is asserted anywhere in this repository.

1. Blocking a better submission

limitationwhy it blockswhat would resolve it
No independent truth layer. The only off-catalogue comparison raster is an owner-derived mirror of an SGMC-derived product (data/external/sgmc/, sha256 d569d553…700f). Every candidate decision in this programme is measured against a proxy that (a) shares agency digitisation practice with the catalogue it is meant to be independent of, and (b) is anti-correlated with the published score ladder at Spearman −0.921 inside the top mass band. Surrogate credit that comes from catalogue-hugging geometry is therefore not evidence of real credit — see the rejected flank-band family. A second, independently produced fault layer from a different agency or method (e.g. a state geological survey compilation, or a geodetically/InSAR-derived lineament set), pinned by hash and provenance.
No reachable path to fresh surface data. Probes from the build sandbox: tnmaccess.nationalmap.gov 000, prd-tnm.s3.amazonaws.com 000, portal.opentopography.org 000, www.drivendata.org 000; only github.com and PyPI respond. The competition ships only a link file (1m_DEM_links.csv) for the 1 m DEM; the competition's own high-resolution elevation layer cannot be fetched here. Any hypothesis that needs fresh topography (scarp detection, multi-scale curvature, swale/closed-depression analysis) is unverifiable in this environment and is therefore not called viable. Sandbox egress to the official 3DEP/TNM hosts, or a pre-fetched DEM cached in a GitHub-mirrored repository whose hashes can be pinned.
The training_features.tif stack is the only heavy feature source reachable. Bands already in the file (gravity, magnetics, topography-derived layers, depth-to-base, heat proxy) are the only inputs the programme can test directly. This bounds the hypothesis space to what those 19 bands can support. A reachable external raster mirror with pinned hashes (several GitHub-mirrored candidates are listed in the evidence pages, but licensing for sponsor sharing must be confirmed per layer).
SGMC mirror hash conflict unresolved. derived_sgmc_faults_100m_u8.tif is recorded here as d569d553…700f; an earlier record in this repository used 26d142c4…b5c for the same filename. Every surrogate number in the H4 record is tied to one hash. If the earlier record refers to a different build of the same product, prior comparisons across the programme are not strictly like-for-like. Re-download the product from the USGS/SGMC side and re-pin; not possible from the build sandbox, so the conflict is disclosed rather than resolved.

2. Blocking a stronger claim

  • All (file, score) pairings are assumptions. The public leaderboard exposes no filenames or hashes. The 0.2778 reference and the corpus's 18 other scores are owner-reported. Every use of them is labelled. The leaderboard projection (slope ≈ 1.001, intercept ≈ −0.089, R² 0.913, RMSE 0.011) is a fit to assumptions, not a measurement.
  • No candidate has passed the frozen promotion rule ("beat the incumbent in all four blocked folds"). H4 wins 1 of 4 folds (LM-calibrated 0.286 vs 0.366 reference); H2-B won 0 of 24 blocks. No weekly submission slot has been spent by this repository on the current evidence.
  • The mask convention is a staff clarification, not the rules PDF: the known-fault mask is pixel-exact, and a predicted pixel near a known trace but far from new truth is fully penalised. The reconstructed scoring model depends on this; the shipped file's own validity does not.
  • DTI variance across folds is large (shipped per-fold LM-calibrated 0.268–0.297; on the SGMC surrogate the user-vs-provider spread was larger still). A single mean hides fold-scale behaviour, so fold-wise reporting is mandatory here.

3. Method limitations of the shipped H4 artifact

  • Euler SI = 0 on potential-field data detects contacts, not faults. A contact that truncates magnetised basement at depth can be a fault, but it can also be a lithological boundary. Nothing here distinguishes the two.
  • The −zeros twin is non-standard for reviewers who expect nodata. It is finite everywhere with values exactly 0/1, which is what the portal accepted in past rounds after the [0, 1] rejection; the −nan twin is provided for the sample's convention. Both pass the same audit.
  • The line response is a matched filter with fixed half-length (3 px). Structures shorter or more sinuous than that are suppressed; no scale sweep was run.
  • Depth weighting uses a fixed 700 m scale and cluster weighting a fixed 2 px neighbourhood. Neither was tuned against real scores, only against the surrogate — and the surrogate is known to reward catalogue-hugging geometry, so these parameters are not trustworthy evidence of quality.
  • Binary emission at 1.0 is metric-optimal under the linear index rule, but it forgoes any hedging a graded field might provide if the real index is not linear in the way the rules PDF implies. The rule as published is linear; this is a judgement, not a measurement.

4. Remaining work, in priority order

  1. Find or build an independent truth layer (highest value). Without it, no surrogate-based ranking can be trusted above the metric-shaped gate, and the gate's reference is itself unverified.
  2. Close the emission-vs-gate conflict. The surrogate model and the frozen gate disagree by construction (SGMC credit rewards catalogue proximity; the ladder punishes it). The next measurement that matters is a candidate that is both high-credit in the surrogate's off-catalogue increment and fold-wise stronger than the reference. Until then, the 60,000 px ring-pruned field remains the best available artifact and the emitters keep the band-dwelling guard.
  3. Test the H3 (focal-mechanism) hypothesis only after its source audit threshold is met (≥50 usable mechanisms in ≥8 blocks). The count endpoint was reachable; direct sandbox TLS to the event-detail host was not.
  4. Rebuild the site's evidence pages from the JSON artifacts rather than edited prose, so no page can drift from the receipts (the schema exists in docs/data/*.json; a builder is partly in scripts/build_site.py).
  5. Re-run scripts/audit_submission.py and scripts/validate_h4_blocked.py in CI on every release so the receipts and the shipped bytes can never diverge silently.

5. Known irregularities, flagged

  • The competition site and the rules PDF describe the metric as a distance-weighted Tversky index; the exact treatment of the catalogue mask came from a community clarification by DrivenData staff, not from the rules document.
  • An earlier iteration in this repository emitted a continuous (non-binary) field and claimed a modelled score above the incumbent; that claim and the file are withdrawn, and the [0, 1] form is now binary by default.
  • Historical pages (index-main-before-h2b.html, executive-summary-h40-4.html) are preserved verbatim as history and are not current advice; the current pages are index.html and executive-summary.html.
