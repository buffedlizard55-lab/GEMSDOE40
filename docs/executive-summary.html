How a future approved submission is entered

These are future instructions, not permission to submit H4. First require a reproducible, valid independent gate win, plus complete novelty and format passes. The historical gate must be repaired in a separately registered protocol—not after choosing a result.

  1. Open the official competition in your own account. Confirm eligibility, enrollment and current rules. No passwords or tokens should be put in this repository.
  2. Download the exact approved .tif using the prominent button. Compare its SHA-256 with its receipt. Do not upload an HTML file saved by the browser.
  3. Open New submission. In File to submit, choose the downloaded GeoTIFF. The optional alternative is a ZIP containing exactly one GeoTIFF; this project supplies the TIFF directly.
  4. Paste the approved short note into Note (optional). Keep the unique tracking name and full SHA-256 in the local experiment record.
  5. Only then submit, review the server’s validation response, and save the actual file-level score receipt. An account’s best leaderboard row is not a receipt for a particular file.
  6. Respect the three-per-week limit. Choose one final submission for both prize rounds under the current rules. This research pipeline never performs a DrivenData upload.

Preventing “Predicted values must be in range [0, 1]”

The written H4 file was reopened and checked across all 5,167,373 valid pixels: every value is finite and within [0,1]. All 7,111,787 outside pixels are NaN, matching the sample mask. The feature stack’s −3.4028235e38 sentinel is never copied into predictions.

NaN outside is the requested and documented format. We do not claim NaN itself causes rejection, and do not silently replace the footprint contract with zeros everywhere. A local pass is not a guarantee about an unknown server-side validator; if a future authorized upload fails, retain the exact bytes and error for diagnosis.
