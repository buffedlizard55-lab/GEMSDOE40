How a future approved submission is entered

These are future instructions, not permission to submit H8/H13. First require a reproducible gate win on a registered, source-independent protocol, plus complete novelty and format passes.

  1. Open the official competition in your own account. Confirm eligibility, enrollment and current rules. Never put passwords or tokens in this repository.
  2. Download the exact approved .tif from the prominent button. Compare its SHA-256 with its receipt. Do not upload an HTML file saved by the browser.
  3. Open New submission. In File to submit, choose the downloaded GeoTIFF. A ZIP containing exactly one GeoTIFF is also accepted; this project supplies the TIFF directly.
  4. Paste the approved short note into Note (optional). Keep the unique tracking name and full SHA-256 in the local experiment record.
  5. Submit, then save the server’s validation response and any file-level score receipt. An account’s best leaderboard row is not a receipt for a particular file.
  6. Respect the three-per-week limit. Choose one final submission for both prize rounds. This repository never performs a DrivenData upload.

Preventing “Predicted values must be in range [0, 1]”

Both written files were reopened from disk and re-checked across all 5,167,373 inside-footprint pixels: every value is finite and in [0, 1] (H13 stores exactly 0.0/1.0; H8 is continuous). All 7,111,787 outside pixels are NaN, matching the sample mask, and the feature stack’s −3.4028235e38 sentinel is never copied into predictions.

NaN outside the footprint is the documented sample contract. We do not claim NaN itself causes rejection and do not silently swap zeros for it; a local pass is not a guarantee about the server-side validator. If an authorized upload ever fails, retain the exact bytes and error text for diagnosis.
