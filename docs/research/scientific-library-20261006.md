# Research library and evidence ledger — 6 October 2026

## What is actually being predicted?

The challenge asks for **surface traces of geological faults**, not vent locations, subsurface resource temperature, transmissivity, or commercial capacity. The initial test labels are newly mapped faults; expert review later expands that set. The public catalogue is incomplete and not a representative negative-label set. [Official task and metric](https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/)

A potential-field boundary is evidence of a magnetization/density contrast, **not proof of displacement**. Source depth below an observation plane is not necessarily depth below topography. A fault can be permeable, sealed, or a barrier. Therefore this project separates three questions: (1) does a source exist, (2) is it a fault and where is its surface trace, (3) could it sustain a geothermal system? H4 addresses a limited version of (1) and uses it as uncalibrated evidence for (2). It does not solve (3).

## Data acquisition and semantic irregularities

- `scripts/acquire_data.py` autonomously restored 418,912,844 feature bytes from five pinned GitHub mirror parts, verified each Git blob and the assembled SHA-256, and verified labels/template/proxy separately. No GPU or DrivenData session was needed for H4.
- Direct Python/curl HTTPS to several official and Dropbox hosts fails during TLS setup in this sandbox; the research fetch tool can read official pages. Do not disable TLS verification or call this an official authenticated download. GitHub access works.
- The old download script did not download absent parts, and the old prepare script could exit successfully while inputs were missing. These are corrected.
- Identically named SGMC rasters are **not identical data**: GEMSDOE24 SHA-256 `643cbe…` does not match the research pin `26d142…`; GEMSDOE30 at commit `1f9ac110…` does. The pinned frozen instrument was recovered rather than substituted.
- The template has positive values although the official example is described as all-zero; use it only for grid/footprint. No template label values entered H4.
- Several supplied band descriptions are ambiguous: `tc` is described as “tilt angle or total curvature” in the mirror while official GeoDAWN documentation also discusses radiometric total counts. `depth_to_base_surf` is not safely assumed to be basement or magnetic source depth from its short name alone. Neither band is used by H4. Store raw band tags as evidence, not verified geologic semantics.
- The H33 ZIP offered in its pinned GEMSDOE32 page source has **216 bytes and contains no TIFF**; it contains an entry named as a ZIP. The actual TIFF is readable and audited. Use the TIFF, not that broken archive, for learning.

## What would actually raise the probability of winning?

1. **Repair the validation target before searching more parameters.** There are only 16 truth-bearing frozen blocks, not 24; an 18-win gate is impossible. The all-prior incumbent is itself SGMC-derived. A new protocol needs whole fault-system withholding, spatial buffers appropriate to the largest feature window, and independent source/version provenance. Preserve the old experiment and choose the new gate before seeing new results.
2. **Close the inverse-to-surface gap.** H4 provides effective source depth, not verified ground-depth or surface fault location. Obtain the official survey altitude/drape metadata; quantify terrain and processing errors on synthetic draped contacts before projecting source planes.
3. **Distinguish lithologic contacts from displaced structures.** Test finite-step models and coherent depth-plane geometry (H5/H6), with local 3DEP scarp/stratigraphic offset confirmation where it exists. Do not treat proximity to the catalogue as an independent physical feature.
4. **Treat geothermal evidence as corroboration, not substitute labels.** Official thermal/chemistry/MT observations can guide expert prioritization after geologic evidence, but need measured coverage and bias audits before a region-wide model.
5. **Do not optimize on unsupported score extrapolations.** Related TIFFs, repeated weekly leaderboard measurements, and synthetic labels calibrated to those scores are not independent tests. The 0.2778 user report is useful history, not a calibration target that can manufacture truth.

No universal or guaranteed winning solution is claimed. These are falsifiable next experiments, not a promise to beat 0.3345.
