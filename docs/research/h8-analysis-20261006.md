# Why `h33-h33-2-b2` = 0.2778 is the family's best, and what beating 0.3195 requires

*Measured 6 October 2026. Every number below is either read from the committed
receipts named in the text or recomputed in this session from
`data/prior/` (279 byte-verified prior rasters), `data/labels.tif`,
`data/external/derived_sgmc_faults_100m_u8.tif` and
`docs/data/instrument-audit-20261006.json`. Nothing here is an organizer score
except the 16 values that were already recorded as owner-reported leaderboard
scores in that audit file; those are labelled as recorded, not verified.*

## 1. The metric, reduced to one inequality

The official metric is the distance-weighted Tversky index
(D = 300 m, α = 0.2, β = 0.8) with a triangular kernel
`k(d) = max(0, 1 − d/300 m)`. Writing `T = TP_w`, `M = Σ p` for emitted mass,
`C_pred = Σ_x p(x)·k(x, nearest truth)` and `N` for the hidden truth size, the
exact binary form implemented and pinned in `src/gemsdoe40/emission.py` is

```
DTI = T / (0.8·N + 0.2·M + 0.2·(T − C_pred))
```

Because α + β = 1, adding one unit of mass whose best achievable kernel credit
is `k` changes the denominator by exactly `0.2` **whatever k is**, and changes
the numerator by `k` only if that unit is the best one for some truth pixel.
Hence

> **Marginal rule.** An emitted unit raises the score iff `k > 0.2·DTI`.

At the family's best recorded score (0.2778) the bar is `k > 0.0556`, i.e. the
unit must lie within **283 m of a hidden fault pixel** — and it must be the
closest emitter to that pixel, otherwise it earns nothing while still paying
0.2. The symmetric deletion rule is
`(1 − 0.2·D)·L < 0.2·D·S`: at D = 0.2778 a prune is profitable as long as the
mass removed gives back less than **5.88 %** of its own weight in true-positive
credit (the exact number recorded in `docs/data/h33-measured-analysis.json` as
`tp_loss_per_fp_saved_limit_at_owner_best = 0.0588285`).

Two consequences that decide everything below:

1. **Mass is a liability with a threshold, not a cost.** A file can only afford
   mass that lands inside 300 m of the hidden truth.
2. **Credit is earned per truth pixel, once.** Redundant mass — two emitters
   inside one 300 m kernel of the same fault pixel — earns nothing for the
   second emitter.

## 2. What the best file actually did (measured, not inferred)

`docs/data/h33-measured-analysis.json` (re-verified this session):

| quantity | value |
|---|---|
| base file `p28-h27-4-d28` (recorded 0.2708) | 40,199 positive pixels |
| best file `h33-h33-2-b2` (recorded 0.2778) | 37,654 positive pixels |
| pixels removed | **2,545 (6.33 %)** |
| pixels added | **0** |
| distance range of the removed pixels to the catalogue | 141.4 – 200.0 m |
| minimum distance of the surviving pixels to the catalogue | 223.6 m |

The best submission in this family is therefore **a deletion**: it removed
exactly the pixels that sat in the 140–200 m moat around the known USGS /
INGENIOUS traces. Under the marginal rule those pixels had at most
`k = 1 − 1.41/3 = 0.53` credit available and, given that the hidden target is
*not* the catalogue, almost certainly none. Removing them converts their fixed
0.2-per-unit denominator cost into a gain.

This is consistent with the staff ruling that known USGS/INGENIOUS pixels are
masked out of evaluation (DrivenData staff, 2026-09-16,
<https://community.drivendata.org/t/scoring-clarification-are-known-usgs-ingenious-faults-masked-when-scoring-and-are-they-in-the-final-round-label-set/11516/2>):
credit can never be earned *on* those pixels, so a prediction placed there is at
best free and at worst the neighbour of a free pixel — and 140–200 m away is
outside the mask, so it pays the full 0.2.

Measured in this session: the winning file's own catalogue credit density is
`w = 0.0074` with **zero** dots within 100 m of any of the 60,988 catalogue
pixels (by construction — the 223.6 m minimum above). A file that scores 0.2778
is therefore invisible to any instrument that measures "agreement with the
catalogue". That single fact invalidates the entire catalogue-based promotion
idea, and it is why the family's earlier instrument search kept failing.

## 4. The hidden credit density, measured from the recorded scores

Inverting the metric with `C_pred ≈ T` (the family's own H33 finding) gives each
artifact's **implied mean credit per emitted pixel against the hidden truth**:

```
w_i = D_i · (0.8·N + 0.2·M_i) / M_i
```

| N (hidden truth px) | best file (37,654 px, 0.2778) | worst file (516,738 px, 0.0748) |
|---|---|---|
| 2,000 | 0.067 | 0.015 |
| 5,800 | 0.090 | 0.016 |
| 20,000 | 0.174 | 0.017 |

The family's best file averages ~0.09 credit units per dot; the worst ~0.016.
The ordering is stable for every N in 2,000–40,000, so the conclusion does not
depend on the unknown truth size.

## 5. What beating 0.3195 requires — arithmetic, not aspiration

Solving the same relation for the credit density a submission must reach:

| mass | required w for DTI = 0.3195 (N = 5,800) | meaning |
|---|---|---|
| 20,000 | 0.162 | 1.8× the best recorded placement quality |
| 37,654 | 0.103 | 1.15× the best recorded placement quality |
| 60,000 | 0.089 | the best recorded quality, kept up over 60 % more mass |
| 100,000 | 0.081 | best-quality dots at 2.7× the mass |

So the gap to the top of the public leaderboard (0.3345 / 0.3262 / 0.3222 /
0.3195 observed 2026-10-06) is **not** a gap in exotic data: it is roughly a
15–25 % improvement in *credit per emitted pixel* at the family's own mass, or
the same quality extended to ~1.6× more dots. That is the target the next
sessions should be steered by, and it is why the two levers that follow from
§1 — (i) prune every emitter that cannot reach 283 m of a plausible fault, and
(ii) add emitters only where independent evidence says a *new* fault is — matter
more than any model upgrade.

## 6. The instrument problem, stated plainly

The family's instrument audit requires a truth model whose leave-one-out
ranking of the 16 recorded artifacts reaches ρ ≥ 0.8 with no mass-only
explanation. This session tested four new instrument families against that
requirement and none qualifies:

* catalogue credit density (`data/labels.tif` as truth): ρ = **−0.285**;
* SGMC-off-catalogue credit density: ρ = **+0.491**;
* emitted mass: ρ = **−0.650**;
* score-anchored peer-consensus credit (LOO, tier 4/6/8): ρ = **+0.53 to +0.70**.

**Irregularity to flag:** with the data available to this repository, the
user's rule "validate the top candidate on the spatially-blocked holdout before
spending a weekly submission slot" cannot be satisfied, because no local
holdout has demonstrated ranking power over the recorded scores. Any claim that
a new file beats the current holdout best is therefore a claim about an
instrument that does not predict the leaderboard. The honest options are to
(a) hold the submission and spend the next session building a truth model that
does clear ρ ≥ 0.8, or (b) submit with an explicit, recorded prediction and
accept the slot risk. This session takes option (a) for the generated file and
records the reasoning here.

## 7. The ranked route to 0.32+ (registered in full in the H8 preregistration)

1. **H14 — tip / step-over / along-strike extension of *existing* systems.**
   DrivenData staff, 2026-09-23, thread "Where do you draw the line?" post 2:
   "For the purposes of this competition, 'new fault' means 'any fault pixel not
   already captured by USGS/INGENIOUS' and can include newly mapped geometry of
   an existing fault system." (<https://community.drivendata.org/t/where-do-you-draw-the-line/11536/2>)
   Testable now with a leave-the-tips-out protocol on the provided catalogue; it
   is the only hypothesis whose target set is partly observable in the data we
   already hold.
2. **H15 — finite-step gravity inversion** (Reid & Thurston 2014: a finite
   gravity step is SI = −1; the SI = 0 vertical-derivative arm used by H4/H7/H8
   is only a local top-edge approximation).
3. **H16 — 1 m lidar scarp re-mapping** across the full footprint (3DEP; the
   competition data tab ships `1m_DEM_links.csv`, and the repo's own 3DEP scarp
   features already hold the best measured catalogue skill of any layer,
   AUC 0.5914 for `upface_max`).
4. **H17 — microseismicity-aligned structures** (bands 16/10; cheap, weak
   measured skill).
5. **H13 — Euler depth-consensus as a *filter* over H14 geometry** (measured
   this session: the H4 Euler cloud's weighted mean distance to the catalogue
   is 32.95 px with P(d < 100 m) = 0.0099 against a random-footprint baseline of
   0.0115 — the cloud carries no catalogue-locating skill, so it may only be
   used as a filter where it is independently calibrated).
